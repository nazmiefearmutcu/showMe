# VCAP — source-aware venture capital research

Approved intent: the user approved the prior source-aware draft and explicitly requested a complete plan and implementation on 31 October 2026. Scope is global totals, country comparisons, Turkey and crypto/Web3. This is one function, not a company/deal discovery database. Existing unrelated MEET edits must remain untouched. No purchase, vendor account, publication, or Git push is authorized.

## Product

Register VCAP in the function palette as a macro research pane. Default to the useful OECD country view (USA, annual investment, total stage, USD). Other scopes remain first-class tabs. Users select sources, countries, metric, stage, frequency, unit and years; compare source series, inspect provenance, import owned/licensed series and export the displayed observations. All screens must have loading, empty, unsupported, error and cached-data explanations.

Every number remains source-specific. Never sum countries into a world total; never add Turkey or crypto onto a global total; never splice sources or fabricate missing periods. Fund fundraising, startup investment, deal counts and valuation are distinct. Do not describe every crypto raise as VC. No predictions or confidence score.

## Data access

OECD: automatic HTTPS CSV from fixed SDMX host/dataflow OECD.SDD.TPS,DSD_VC@DF_VC_INV,1.0, annual USD_EXC and PT_B1GQ; preserve UNIT_MULT and missing values, stage and country coverage, observation flags and update dates. Request the bulk file once per 24 hours, explicit refresh subject to at least 60-second cooldown. Bound request size and timeout; single-flight requests. Persist release snapshots and allow stale data on network failure with an explicit stale flag. Never infer Turkey or WORLD availability from generic SDMX codelists.

DefiLlama: optional server-side SHOWME_DEFILLAMA_API_KEY; fixed pro-api.llama.fi/{key}/api/raises endpoint. Never return/log the key or keyed URL. No subscription or credential is created by this work. Preserve original raises scope and announcement-date basis; filter token/public/ICO/unknown types conservatively when strict VC is requested. Broad funding view must explicitly include token financing and cannot silently become strict VC. Missing monetary amounts remain missing; deal counts may include undisclosed amounts with that coverage disclosed. No geographic inference from investor location.

KPMG/PitchBook, Crunchbase, CB Insights, Dealroom, startups.watch and Galaxy: source catalogue with research/terms links plus validated import of user-provided datasets. Public reports are references, not an assumed redistribution license or an undocumented scrape API. The function must be usable for every scope through the same import path; unavailable automated access must be clearly stated. Custom sources can be imported. Store locally; do not transmit imported data to cloud AI.

## Stable service contract

POST/GET /api/fn/VCAP uses the existing engine. Query params: action=query (default), scope=countries|global|turkey|crypto, source_ids (list or comma separated), geographies (ISO3 codes/WORLD/TUR_DIASPORA), metric=investment|deals|fundraising, stage=total|seed|early|late, frequency=annual|quarterly, unit=USD|PERCENT_GDP|COUNT, financing_scope=vc|all_raises (default vc), start_year=2007, end_year=current year, refresh=false, optional vintage snapshot id. Strict types/ranges and invalid combinations return input_error without fetching. Financing scope is preserved in normalized records and comparison signatures; all_raises is labelled reported crypto financing including token sales, never pure VC.

Actions import (dataset object) and versions (optional source_id) reuse POST dispatch. Local import has a 2 MB JSON limit and 10,000 observations limit. It is atomic and validated before storage; repeats of identical content are idempotent. No arbitrary network/file paths are accepted. Snapshots use SQLite transactions in SHOWME_VCAP_DIR or the platform ShowMe data directory and content hashes; never overwrite a prior release. Snapshot selection must reproduce older imports. Importing an older publication must not silently replace a newer publication.

Import dataset schema version 1: source_id (catalogue id or custom slug), source_name (required for custom), source_url (https reference), published_at (ISO date/time), methodology (nonempty), methodology_version (nonempty), geography_basis=company_hq|fund_manager|source_defined, date_basis=announced|closed|source_defined, sector=all|crypto|web3|source_defined, observations array. Every observation: scope, geography, period (YYYY or YYYY-Qn), metric, stage, unit, value (finite nonnegative number or null), status=reported|provisional|missing, optional coverage_note. Missing status requires null; numeric zero is valid. Frequency derives from period and stage/group observations cannot be duplicated in one snapshot. Percent >100 and fractional/negative counts are invalid. Unknown fields may be ignored but required semantic fields cannot be guessed.

Query result data: status, reason/next_actions when needed; rows (normalized observations with source_id, source_name, scope, geography, period, period_start, period_end, frequency, metric, stage, unit, value, status, published_at, retrieved_at, snapshot_id, vintage, methodology_version, geography_basis, date_basis, sector, source_url, coverage_note), sources (catalogue availability/capabilities and references), snapshots (history), series (source/geography/stage series with actual periods including nulls), summary, comparison (comparable and blocked pairs with reasons), methodology. Standard FunctionResult metadata contains data_mode=official|imported|mixed|unavailable and cached/stale flags; no fake live label. UI must read this payload rather than generic fetched_at as the observation date.

Comparability requires equal scope, geography, metric, frequency, stage, unit, sector, geography_basis, date_basis, and a compatible methodology. Independent publishers' reported totals can be shown side by side but a normalized % gap is blocked unless semantics explicitly match; source lineage is displayed. Annualization/TTM is only allowed for complete compatible periods and never presented as reported data. Initial implementation may omit derived TTM rather than invent it.

## UI

Use existing Pane, typography, theme CSS variables, native controls and dense tables. One new VCAP-specific stylesheet; no global redesign. Dedicated responsive accessible SVG plot: investment bars, distinct source colors, actual chronological coordinates, null gaps, exact values in accessible titles, independent currency/count axes via separate metric views. The table is the accessible exact-value equivalent. Scope/source changes never leave mismatched old data labelled as the new query. Preserve persisted controls, enable refresh, show clear unavailable/source access details, allow an import file (JSON/CSV with documented schema), downloadable empty template and CSV/JSON export. Escaped CSV values must not become spreadsheet formulas. Keep exports as local downloads; no arbitrary file writes via API. All controls keyboard operable, errors announced, labels fit at 960px and larger.
